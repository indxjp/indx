# Code Review

Code review keeps our codebase clear and shares knowledge across the team. It is
referenced from the [Engineering Guide](guide.md).

## What reviewers look for

- **Correctness.** Does the change do what it says, with a test that would fail
  without it?
- **Clarity.** Could a new hire understand this in six months?
- **Scope.** Is the pull request small and focused, per our small-reversible-changes
  principle?

## Etiquette

- Review within one working day; an unreviewed pull request blocks a teammate.
- Comment on the code, not the person.
- Approving means "I would be comfortable owning this change."

## Who reviews

Anyone on the team can review. For larger changes, ask the area owner listed in the
[team directory](../people/team.md).
